# MagicWX 开发文档

> 状态：Android 17 / v1.1.0 发布候选基线
> 更新日期：2026-07-31

## 1. 技术边界

MagicWX 当前是单模块 Android 应用，使用 Kotlin、Jetpack Compose、Material3、ViewModel、Kotlin Flow 和 ONNX Runtime Android。v1.1.0 发布候选目标是适配 Android 17 / API 37、修复已知质量问题并生成 GitHub Release 原型包，不引入新的运行时、服务端或模型包格式。

## 2. 核心链路

```text
MainActivity
  -> MainApp
  -> MainViewModel
  -> ModelDownloader
  -> ITokenizer / RWKVTokenizer / HFTokenizer
  -> RWKVModel
  -> ONNX Runtime
```

`MainViewModel` 负责 UI 状态，`ModelDownloader` 负责本地模型目录和 ready 判定，`RWKVModel` 负责 ONNX 会话和生成，分词器实现只通过 `ITokenizer` 暴露。

## 3. 模型包规则

- RWKV 模型：模型目录必须存在非空 `.onnx` 文件。
- Transformer 模型：模型目录必须存在非空 `.onnx` 文件和非空 `tokenizer.json`。
- `.downloading` 文件、零字节文件、缺 tokenizer 的 Transformer 目录不得进入已下载列表。
- Transformer 缺 tokenizer 时必须失败，禁止回退到 RWKV 分词器。

## 4. 安全与备份

应用私有目录可能包含下载模型、运行状态和用户输入。阶段二禁用 Android 系统备份和设备迁移复制，后续如需迁移偏好，必须先完成数据分类和显式导入导出设计。

## 5. 验证命令

```bash
./gradlew help
./gradlew build --dry-run
./gradlew testDebugUnitTest
./gradlew assembleDebug
./gradlew lintDebug
./gradlew assembleRelease
```

设备验证优先覆盖模型选择、下载、加载、聊天、停止、重置、切换和删除。没有真实模型 dry-run 证据前，不得把 Transformer 候选描述为正式支持。

## 6. Android 17 适配说明

- `compileSdk` 与 `targetSdk` 使用 API 37。
- 当前 App 不使用局域网发现、短信/OTP、自定义通知或固定方向限制，因此本轮没有对应业务迁移代码。
- 大屏、折叠屏、平板和真机 Android 17 行为仍需设备验证后才能进入生产口径。
- GitHub Release APK 仅用于原型验证，不携带签名密钥和模型权重。
