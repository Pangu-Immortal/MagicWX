# MagicWX 开发文档

> 状态：LocalDream 本地生图 Phase 1（SD1.5 CPU）全链路完成 + RWKV/ONNX 聊天基线
> 更新日期：2026-08-06

## 1. 技术边界

MagicWX 当前是单模块 Android 应用，使用 Kotlin、Jetpack Compose、Material3、ViewModel、Kotlin Flow、Room、ONNX Runtime Android 与独立 native 生图后端。文本聊天已实现 `BUILTIN_TEXT`、`ONNX_TEXT_GENERATION`、`LITERT_LM` 三类 adapter；本地生图已实现 SD1.5 CPU 管线（MNN native 后端，txt2img / img2img / inpaint 真机验证通过）。NPU/QNN 管线（SD1.5 NPU、SDXL、Anima、超分）已登记模型与门禁，待 QNN runtime 集成后开放。未验证的 ASR、VAD、TTS、Vision、VLM runtime 不暴露给用户。

## 2. 核心链路

```text
聊天：MainActivity -> MainApp -> MainViewModel -> ModelRuntimeAdapterFactory
      -> BuiltinTextAdapter / OnnxTextGenerationAdapter / MediaPipeLlmAdapter
      -> ModelDownloader -> ITokenizer -> RWKVModel / ONNX Runtime

生图：ImageGenerationScreen(UI) -> MainViewModel -> ImageGenerationService(FGS)
      -> ImageBackendService(FGS, 持有独立 native 进程)
      -> libmagicwx_image_backend.so（localhost:18081，SSE /generate、/tokenize、/upscale）
      -> MNN（静态链接，LOW_MEMORY + UNet fp16/VAE fp32）
      -> 生成结果写 filesDir/generated_images，COMPLETED 事件 -> Room 历史
```

`MainViewModel` 负责 UI 状态并通过 `ModelRuntimeAdapterFactory` 选择运行时 adapter。`ModelDownloader` 负责本地模型目录和 ready 判定（多文件模型包按 `requiredRuntimeFiles` 校验，zip 顶层文件夹布局经 `getRuntimeDirectory` 归一）。候选模型只进入 `ModelRegistry.allModels`，首页只读取 `ModelRegistry.models`。

## 3. 本地生图后端架构（Phase 1 完成）

- **进程隔离**：生图在独立 native 可执行 `libmagicwx_image_backend.so`（随 APK 打包，`ProcessBuilder` 启动），崩溃不影响主 App；`ImageBackendService` 作为 specialUse 前台服务持有进程生命周期。
- **构建**：MNN 源码静态编译（pin alibaba/MNN@3db3cc90，flag 对齐 local-dream：LOW_MEMORY / CPU_WEIGHT_DEQUANT_GEMM / OPENCL / TRANSFORMER_FUSE），全链路强制 `-O3 -DNDEBUG`（Debug 变体同样生效）。
- **精度策略**：UNet 走 fp16（MNN_ARM82，提速主力），VAE 编解码与 CLIP 强制 fp32（fp16 下 latent 动态范围导致数值崩塌出黑图）。
- **协议**：`/generate` SSE（progress/complete/error，图像 base64）、`/tokenize`（CLIP 计数）、`/upscale`（RGB 裸字节 + 头部，MNN 路径就绪，等 QNN/`.mnn` 超分模型）。
- **能力边界**：CPU 管线支持 txt2img / img2img / inpaint；ultrafix 为 QNN/NPU 专属（与上游 local-dream 一致）；尺寸门禁 ≤512×512（attention 内存随序列长度平方增长，768 在中端 8GB 机会 OOM）。
- **已知设备策略**：三星 Android 16 对退前台的 FGS 强杀，生图需 App 保持前台；specialUse + COMPLETED 事件前置已把杀窗口损失降到最低。

## 4. 模型包规则

- RWKV 模型：模型目录必须存在非空 `.onnx` 文件。
- Transformer 模型：模型目录必须存在非空 `.onnx` 文件和非空 `tokenizer.json`。
- 多模态候选模型：必须声明 `capability`、`adapterType`、`visibility` 和不可用原因；adapter 未接入时不得下载或加载。
- 显式资产模型：通过 `ModelAsset` 声明主模型、tokenizer、外部数据、配置、声音、标签、task、encoder、decoder 等文件。
- LocalDream 生图模型：zip 包解压后按 `requiredRuntimeFiles` 校验完整布局（tokenizer.json / clip / unet / vae 全套），嵌套顶层文件夹自动归一。
- `.downloading` 文件、零字节文件、缺 tokenizer 的 Transformer 目录不得进入已下载列表。
- Transformer 缺 tokenizer 时必须失败，禁止回退到 RWKV 分词器。

## 5. 安全与备份

应用私有目录可能包含下载模型、运行状态和用户输入。阶段二禁用 Android 系统备份和设备迁移复制，后续如需迁移偏好，必须先完成数据分类和显式导入导出设计。

## 6. 验证命令

```bash
./gradlew help
./gradlew build --dry-run
./gradlew testDebugUnitTest
./gradlew assembleDebug
./gradlew lintDebug
./gradlew assembleRelease
```

设备验证优先覆盖模型选择、下载、加载、聊天、停止、重置、切换和删除；生图覆盖 txt2img / img2img / inpaint、历史落库与复用。没有真实模型 dry-run 证据前，不得把 Transformer 候选描述为正式支持。

## 7. Android 17 适配说明

- `compileSdk` 与 `targetSdk` 使用 API 37。
- 当前 App 不使用局域网发现、短信/OTP、自定义通知或固定方向限制，因此本轮没有对应业务迁移代码。
- 大屏、折叠屏、平板和真机 Android 17 行为仍需设备验证后才能进入生产口径。
- GitHub Release APK 仅用于原型验证，不携带签名密钥和模型权重。
